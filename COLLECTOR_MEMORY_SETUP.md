# CyberpetsAI Persistent Collector Memory v1.0

## Deployment

This update retains `server.js` as the Vercel entry point, and keeps the existing OpenAI/OpenSea Vercel environment variables. It adds `DATABASE_URL` (PostgreSQL connection string). Provision a PostgreSQL database reachable from Vercel, add `DATABASE_URL` in Vercel project settings, and redeploy. Tables are created automatically on first request. Use a provider connection URL with valid TLS certificates.

Install dependencies using `npm install` and commit the updated `package-lock.json` generated by that command before deploying. No scheduled jobs are needed.

**Important:** `.env` is intentionally excluded from the delivery ZIP. Maintain actual secrets in Vercel environment settings, not Git.

## Behavior

- Clicking Connect Wallet requests a nonce, asks the wallet to sign a domain/chain/address-bound message, and exchanges the signed message for a secure HTTP-only session cookie.
- On every signed connection the server refreshes CyberpetsAI holdings from OpenSea (including pagination).
- The first connection creates a baseline; subsequent connections compare token IDs against the previous snapshot. New received/sent observations are persisted as pending acknowledgements.
- The browser displays changes and asks whether to mark them as seen. Declining leaves them pending for the next connection.
- Session data, collector profiles, and pending activities survive Vercel instance restarts.
- No blockchain polling or scheduled sync is used.

## Limitations

- Ownership snapshots detect **net ownership changes**, not individual Polygon transactions, sales, or prices. A token that leaves and returns between connections will not be detected. This release does **not** query Polygonscan or Polygon transfer logs.
- The existing chat history remains session-scoped, not long-term AI memory.
- The current session is valid for 30 minutes since its last API activity. Sessions may be invalidated by wallet logout or cookie expiry.
- The client uses the wallet's signing UI for each new authentication; a remembered wallet connection alone is not authentication.
- OpenSea API failures prevent synchronization and do not overwrite the saved snapshot.
- For deployments with large collections, the NFT pagination cap is 20 pages and unacknowledged results are returned in batches of 100.

## Smoke test

1. Configure DATABASE_URL and deploy.
2. Connect a wallet holding CyberpetsAI NFTs and sign the message. Confirm chat unlocks.
3. Refresh the page while still connected; verify the session restores without signing again.
4. Log out/expire the session and reconnect: see the welcome-back message.
5. After a verified NFT ownership change, reconnect: verify the activity notification appears. Decline acknowledgement, reconnect and verify it persists. Accept, reconnect and verify it no longer appears.
6. Verify an address-only POST to `/api/auth` fails, and a reused nonce fails.
7. Confirm a different wallet does not restore the previous wallet's profile or active NFT preference.
